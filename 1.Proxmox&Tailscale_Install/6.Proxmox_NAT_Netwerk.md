## 3. Netwerkontwerp

### 3.1 Keuze van het IP-bereik

Er is gekozen voor `10.50.0.0/16` om overlap met bestaande VIVES-netwerken (10.10.x.x en 10.20.x.x) te vermijden.

> ⚠️ Controleer bij VIVES dat `10.50.0.0/16` daar niet in gebruik is. Een /16 is een grotere reservering dan een /24 en heeft meer kans op overlap.

## 4. NAT-bridge `vmbr1`

### 4.1 Doel

VM's op `vmbr1` hebben geen fysieke poort. Ze krijgen internettoegang doordat de Proxmox-host hun verkeer via NAT (masquerade) door `wlp3s0` stuurt.

### 4.2 Configuratie (`/etc/network/interfaces`)

Het volgende blok staat boven de regel `source /etc/network/interfaces.d/*`:

```text
auto vmbr1
iface vmbr1 inet static
        address 10.50.0.1/16
        bridge-ports none
        bridge-stp off
        bridge-fd 0
        post-up   echo 1 > /proc/sys/net/ipv4/ip_forward
        post-up   iptables -t nat -A POSTROUTING -s 10.50.0.0/16 -o wlp3s0 -j MASQUERADE
        post-down iptables -t nat -D POSTROUTING -s 10.50.0.0/16 -o wlp3s0 -j MASQUERADE
```

| Regel | Functie |
| --- | --- |
| `address 10.50.0.1/16` | IP van de host op de bridge (gateway voor VM's) |
| `bridge-ports none` | Interne bridge zonder fysieke poort |
| `ip_forward` | Laat de host verkeer doorsturen |
| `MASQUERADE` | Vervangt het bron-IP door het WiFi-IP bij uitgaand verkeer |

### 4.3 Activeren

Alleen de nieuwe bridge activeren. `systemctl restart networking` wordt vermeden, omdat de WiFi-verbinding daarbij kan wegvallen en de SSH-sessie verbroken wordt.

```bash
iptables --version || apt install -y iptables
ifup vmbr1
```

### 4.4 Controle

```bash
ip a show vmbr1
sysctl net.ipv4.ip_forward
iptables -t nat -L POSTROUTING -n
grep -A8 vmbr1 /etc/network/interfaces
```

Verwacht resultaat (zo gecontroleerd):

* `vmbr1` staat `UP` met `inet 10.50.0.1/16` (status `UNKNOWN` is normaal voor een bridge zonder poorten).
* `net.ipv4.ip_forward = 1`
* Een `MASQUERADE`-regel voor `10.50.0.0/16`. De regel `ts-postrouting` hoort bij Tailscale en blijft staan.
* Het bestand `/etc/network/interfaces` bevat het volledige blok, zodat de bridge na een reboot terugkomt.

## 7. Authentik installeren (gepland)

```bash
mkdir -p /opt/authentik && cd /opt/authentik
curl -O https://docs.goauthentik.io/docker-compose.yml
echo "PG_PASS=$(openssl rand -base64 36 | tr -d '\n')" >> .env
echo "AUTHENTIK_SECRET_KEY=$(openssl rand -base64 60 | tr -d '\n')" >> .env
docker compose up -d
```

* Eerste setup: `http://<ip>:9000/if/flow/initial-setup/` (met slash aan het einde) om het wachtwoord van `akadmin` in te stellen.
* Het IP is alleen intern bereikbaar. Toegang vanaf de pc via een SSH-tunnel:

```bash
ssh -L 9000:10.50.0.10:9000 root@192.168.128.10
```

Daarna `http://localhost:9000/if/flow/initial-setup/` openen.

### 7.1 E-mail (SMTP)

Eigen mailbox als afzender; andere adressen zijn alleen ontvangers. Toevoegen aan `/opt/authentik/.env`:

```text
AUTHENTIK_EMAIL__HOST=smtp.gmail.com
AUTHENTIK_EMAIL__PORT=587
AUTHENTIK_EMAIL__USERNAME=<adres>
AUTHENTIK_EMAIL__PASSWORD=<app-wachtwoord>
AUTHENTIK_EMAIL__USE_TLS=true
AUTHENTIK_EMAIL__FROM=<adres>
```

> ⚠️ Gebruik een app-wachtwoord (2FA vereist), niet het gewone wachtwoord. Zet het alleen in `.env` en nooit in documentatie of op GitHub. Voor testgebruikers kan een plus-adres (`naam+student1@gmail.com`) gebruikt worden.

## 9. Troubleshooting

| Symptoom | Oorzaak | Oplossing |
| --- | --- | --- |
| VM heeft geen internet | NAT niet actief | `iptables -t nat -L POSTROUTING -n` controleren, `ifdown vmbr1 && ifup vmbr1` |
| `ping 1.1.1.1` werkt, `deb.debian.org` niet | DNS | `nameserver 1.1.1.1` in `/etc/resolv.conf` van de VM |
| Debian-installer blijft hangen op netwerk | Geen DHCP | Netwerk handmatig configureren |
| `vmbr1` na reboot weg | Configuratie niet opgeslagen | `grep -A8 vmbr1 /etc/network/interfaces` |
| `iptables: command not found` | Pakket ontbreekt | `apt install -y iptables` |
| Verbinding valt weg na netwerkwijziging | `networking` herstart over WiFi | Alleen `ifup`/`ifdown` van de betreffende interface gebruiken |
